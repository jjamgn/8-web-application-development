01

Kiến trúc, component và state owner

DỮ LIỆU BAN ĐẦU

Seed JSON

Khởi tạo danh sách từ dữ liệu mẫu của bản SSR. StudentApp sao chép từng bản ghi seed để khởi tạo state.

STATE DÙNG CHUNG

StudentApp

Giữ danh sách hiện tại và xử lý yêu cầu thêm sinh viên từ form.

GIAO DIỆN

Các component con

Stats, List và Filters hiển thị màn hình danh sách. Form giữ dữ liệu nhập và gọi callback của cha.

TRÌNH DUYỆT

React → DOM

React render từ state và props, sau đó cập nhật các phần tử thực tế trên trang.

Dữ liệu tính từ state

  • classNames = getClassNames(students): danh sách lớp đã chuẩn hóa, loại trùng và sắp xếp.
  • visibleStudents = filterStudents(students, { className: selectedClass, query }): kết quả kết hợp lọc lớp và tìm kiếm.
  • students.length và classNames.length: tổng sinh viên và số lớp.

Ref phục vụ focus

heading trong StudentApp trỏ tới tiêu đề; effect theo activeView đưa focus về tiêu đề và cuộn lên đầu trang.

inputs trong StudentForm chứa bốn ref để focus ô lỗi đầu tiên. Các ref không phải state và thay đổi ref không tự kích hoạt render.

Luồng thêm sinh viên

StudentForm.handleSubmit
  → preventDefault() → onAdd(values)
  → StudentApp.handleAddStudent
  → validateStudent(input, students)
  ├─ Lỗi: trả { ok: false, errors }
  │       → Form cập nhật errors + focus
  └─ Hợp lệ: tạo ID → cập nhật students
          → clearFilters() → đặt notice
          → activeView = 'list'
          → Form unmount, List/Stats render

Luồng lọc và tìm kiếm

StudentFilters: chọn lớp / nhập từ khóa
  → onClassChange / onQueryChange
  → StudentApp cập nhật selectedClass / query
  → tính lại visibleStudents
  → StudentList nhận students mới qua props
  → React cập nhật bảng
02

Workflow theo từng thao tác

Mở ứng dụng và xem danh sách

Việc tải tài nguyên diễn ra khi mở trang; danh sách được dựng bằng JavaScript trong trình duyệt.

  1. Tải HTML và tài nguyên

    Trình duyệt nhận trang chứa root cùng JavaScript/CSS của ứng dụng.

  2. Gắn React vào root

    ReactDOM gắn cây component vào DOM. Seed được dùng để khởi tạo state của StudentApp.

  3. Render danh sách

    StudentApp truyền danh sách qua props; StudentList mô tả các hàng và React cập nhật DOM.

Nhập đủ thông tin → thêm → danh sách cập nhật

Form được xử lý bằng sự kiện submit, hỗ trợ cả nút gửi và phím Enter.

  1. Nhận sự kiện submit

    Người dùng nhập mã sinh viên, họ tên, email và lớp. Event handler nhận yêu cầu gửi form.

  2. Chặn gửi mặc định

    event.preventDefault() chặn hành vi gửi/điều hướng mặc định. Lệnh này chưa thêm sinh viên.

  3. Đọc và kiểm tra dữ liệu

    StudentForm gọi onAdd(values). StudentApp chạy validateStudent(input, students): chuẩn hóa bốn trường, kiểm tra hợp lệ và mã sinh viên/email trùng.

  4. Tạo sinh viên có ID riêng

    Nếu hợp lệ, StudentApp tạo ID bằng crypto.randomUUID() và bản ghi gồm id, studentCode, name, email, className.

  5. Cập nhật state bằng mảng mới

    StudentApp cập nhật danh sách, chẳng hạn setStudents(prev => [...prev, student]).

  6. React cập nhật giao diện

    StudentApp xóa bộ lọc/từ khóa, đặt thông báo và chuyển về list. StudentForm unmount nên bản nháp mất; StudentList và StudentStats hiển thị dữ liệu mới.

F5 → phiên chạy mới → khôi phục seed

State giữ dữ liệu trong bộ nhớ của phiên ứng dụng hiện tại.

  1. Kết thúc phiên hiện tại

    Tải lại trang làm mất state trong bộ nhớ, bao gồm sinh viên vừa thêm.

  2. Khởi tạo lại ứng dụng

    JavaScript chạy lại; StudentApp khởi tạo danh sách từ seed.

  3. Hiển thị dữ liệu mẫu

    Trở về danh sách mẫu, theo kế hoạch là 20 sinh viên. Không có bước đọc lại dữ liệu đã thêm từ storage.

Giới hạn có chủ đích: không API/database, không ghi JSON ở server, không localStorage. Bản CSR này không lưu lâu dài sinh viên mới.
03

Các bước xây dựng

  1. Phân tích ứng dụng SSR

    Đọc Express/EJS, routes, service và seed JSON; xác định POST + redirect là luồng đang tải lại trang.

  2. Chốt React và thông tin sinh viên

    Bản hiện tại dùng đầy đủ id, studentCode, name, email, className. Form nhận bốn trường nghiệp vụ; ứng dụng tự tạo ID.

  3. Tạo frontend riêng

    Thiết lập React + Vite, HTML root, entry JSX và CSS. Tái sử dụng dữ liệu/bố cục từ SSR.

  4. Đưa dữ liệu vào state

    StudentApp khởi tạo seed; StudentList nhận props và render danh sách.

  5. Nối form với callback

    Xử lý submit, validation, ID mới và cập nhật state để React cập nhật danh sách.

  6. Kiểm chứng và hướng dẫn

    Kế hoạch yêu cầu build, kiểm tra nghiệp vụ và browser; README/verification được nêu là nơi ghi phạm vi và kết quả cuối.

04

Những quyết định và lý do

D01 · CÁCH ĐỒNG BỘ GIAO DIỆN

Dùng React thay cho thao tác DOM thủ công

Vanilla JavaScript yêu cầu tự giữ mảng dữ liệu và DOM đồng bộ. React cho phép mô tả giao diện theo state, đồng thời chia List/Form thành component. Lựa chọn này phù hợp yêu cầu React hoặc framework component tương đương trong kế hoạch.

D02 · THÔNG TIN SINH VIÊN

Dùng đầy đủ các trường như SSR

Form nhận mã sinh viên, họ tên, email và lớp; bản ghi bổ sung ID do ứng dụng tự tạo. Cấu trúc dữ liệu thống nhất với SSR giúp đối chiếu seed, thông tin hiển thị và quy tắc kiểm tra đầu vào giữa hai phiên bản.

D03 · NGÔN NGỮ & CÔNG CỤ

JavaScript + JSX, React + Vite

JavaScript phù hợp mức học hiện tại. JSX diễn tả giao diện bằng component. Vite xử lý module, JSX, dev server và build file tĩnh; plugin React hỗ trợ tích hợp và Fast Refresh.

D04 · QUYỀN SỞ HỮU DỮ LIỆU

State dùng chung nằm ở StudentApp

StudentApp giữ students, activeView, notice, selectedClass và query. StudentForm giữ values/errors cục bộ. classNames và visibleStudents được tính từ state gốc; các component hiển thị nhận props và gọi callback để yêu cầu thay đổi.

D05 · ĐỊNH DANH

ID riêng, key ổn định

Dùng API trình duyệt crypto.randomUUID() cho sinh viên mới, dùng ID làm React key thay vì vị trí trong mảng. Không cần thư viện UUID riêng theo kế hoạch.

D06 · LƯU TRỮ

Seed + state trong bộ nhớ

Phạm vi bài không cần API/database. Dữ liệu mới chỉ tồn tại trong phiên; F5 khôi phục seed. Đây là khác biệt quan trọng với SSR vốn ghi dữ liệu vào JSON trên server.

D07 · SỰ KIỆN & ĐIỀU HƯỚNG

Submit qua handler trên cùng trang

Chặn gửi mặc định, rồi đọc/kiểm tra dữ liệu và cập nhật state. Kế hoạch chọn trạng thái giao diện trên một URL, không tái tạo routes SSR; thao tác thêm không cần chuỗi POST → redirect → GET.

D08 · TÁI SỬ DỤNG CÓ CHỌN LỌC

Chuyển EJS sang JSX, tách logic client

Tái sử dụng seed, CSS và ý tưởng validation. Không import service SSR chứa node:fs, node:path, node:crypto vào browser. Frontend được tách riêng, backend SSR giữ nguyên theo kế hoạch.
