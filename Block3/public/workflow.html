02

Workflow theo từng thao tác

Khởi động server

Chạy npm start → thực thi server.js.

  1. Chọn cổng

    Lấy biến môi trường PORT, mặc định 3000. Kiểm tra số nguyên từ 1–65535.

  2. Tạo ứng dụng

    createApp() cấu hình Express, EJS, static files, form parser, routes và middleware lỗi.

  3. Kiểm tra dữ liệu

    store.initialize() đọc JSON, kiểm tra cấu trúc và bản ghi trùng. Nếu file chưa tồn tại, tạo mảng rỗng.

  4. Mở cổng

    Chỉ gọi app.listen() sau khi dữ liệu đã được kiểm tra thành công.

Nếu dữ liệu hỏng: ghi lỗi tại terminal và không khởi động server. File hiện có được giữ nguyên.

Xem danh sách / lấy sinh viên theo mã lớp

Ví dụ: GET /students?className=24C08.

  1. Gửi yêu cầu GET

    Mở danh sách hoặc chọn mã lớp trong form. Mã lớp được gửi qua query string.

  2. Route gọi handler

    routes/students.js chuyển yêu cầu đến controller.index(req, res).

  3. Đọc danh sách

    await store.list() chờ lượt trong hàng đợi và đọc toàn bộ file bằng fs.readFile().

  4. Lọc ở server

    Trim và chuyển mã lớp sang chữ hoa, rồi so sánh chính xác. Không có mã lớp thì lấy toàn bộ.

  5. Render template

    Truyền danh sách đã lọc, lớp được chọn, các lớp và tổng số vào views/students/index.ejs.

  6. Trả HTML

    Trình duyệt hiển thị bảng và số kết quả. Thống kê tổng sinh viên/số lớp vẫn tính trên toàn bộ dữ liệu.

Không tìm thấy: trả trang HTML với thông báo lớp chưa có sinh viên và nút xem tất cả. Mã lớp trong query được escape khi hiển thị.

Thêm sinh viên mới

GET /students/new render form → người dùng điền dữ liệu → POST /students.

  1. Nhận form

    express.urlencoded() đọc form vào req.body, với giới hạn payload 10 KB.

  2. Vào hàng đợi

    Handler create gọi store.add(). Toàn bộ chuỗi đọc–kiểm tra–thêm–ghi chạy trong cùng một lượt.

  3. Kiểm tra thông tin

    Trim các trường, mã sinh viên viết hoa, email viết thường. Kiểm tra bắt buộc, độ dài, định dạng và trùng mã/email.

  4. Tạo bản ghi

    Dùng crypto.randomUUID() cho ID nội bộ; thêm sinh viên vào mảng vừa đọc.

  5. Lưu JSON

    Ghi JSON hoàn chỉnh vào file tạm cùng thư mục, rồi rename() thay file chính và dọn file tạm.

  6. Chuyển về danh sách

    Trả redirect 303 đến /students?added=1. Trình duyệt gửi GET và hiện thông báo thành công.

Thông tin sai hoặc trùng: trả 422, render lại form, giữ các giá trị đã nhập và hiển thị lỗi theo trường. Lỗi đọc/ghi chuyển sang middleware, trả trang lỗi 500.

04

Những quyết định kỹ thuật

D01 · RENDERING

Chọn SSR bằng Express + EJS

Lý do: yêu cầu gồm danh sách, lọc lớp và thêm sinh viên; HTML form và render server đáp ứng trực tiếp.

Đánh đổi: mỗi lần lọc/gửi form sẽ tải trang; không có cập nhật bảng tức thời kiểu SPA.

D02 · STRUCTURE

Tách routes, controller, service và views

Lý do: route định tuyến; controller điều phối; service quản lý dữ liệu; EJS hiển thị. Dễ đọc và test từng phần.

Cách triển khai: đây là cấu trúc phân lớp gọn, theo tinh thần MVC; không có thư viện ORM hoặc model database riêng.

D03 · STORAGE

Lưu sinh viên trong file JSON

Lý do: theo yêu cầu ban đầu; dễ xem và chỉnh dữ liệu mẫu, không cần cài database.

Đánh đổi: đọc cả mảng và ghi lại toàn bộ khi thêm; phù hợp dữ liệu nhỏ. Khi quy mô tăng, chuyển sang cơ sở dữ liệu.

D04 · ASYNC I/O

Chọn fs/promises + async/await

Lý do: trong lúc chờ đọc/ghi ổ đĩa, Node.js có thể xử lý công việc khác; code vẫn theo thứ tự dễ đọc.

Giới hạn: JSON.parse/stringify vẫn chạy đồng bộ. Async/await tự nó không ngăn hai request ghi đè nhau.

D05 · CONCURRENCY

Đưa thao tác store vào hàng đợi Promise

Lý do: giữ đọc–kiểm tra trùng–thêm–ghi trong một lượt; request sau đọc được dữ liệu request trước vừa lưu.

Đánh đổi: thao tác store thực hiện tuần tự, gồm cả đọc danh sách. Hàng đợi chỉ có hiệu lực trong một tiến trình/store.

D06 · FILE INTEGRITY

Ghi file tạm rồi đổi tên

Lý do: tránh ghi trực tiếp từng phần lên file chính. File tạm đặt cùng thư mục và có tên UUID riêng.

Giới hạn: không thay thế backup hoặc bảo đảm bền vững khi mất điện. JSON hỏng được báo lỗi, không tự ghi đè.

D07 · VALIDATION

Kiểm tra dữ liệu tại server

Lý do: kiểm tra HTML có thể bị bỏ qua. Service kiểm tra lại kiểu dữ liệu, trường bắt buộc, định dạng, độ dài và mã/email duy nhất.

Quy tắc: mã sinh viên 2–30 ký tự chữ không dấu/số/_/-; tên tối đa 100; email tối đa 254; lớp tối đa 50.

D08 · RESPONSE

Post/Redirect/Get và lỗi theo trường

Lý do: sau khi lưu dùng redirect 303; refresh trang danh sách không gửi lại POST. Nhập sai thì trả 422 và giữ dữ liệu form.

Hiển thị: EJS dùng <%= ... %> để escape dữ liệu; lỗi hệ thống chi tiết chỉ ghi tại terminal.

D09 · FILTER

Lọc lớp bằng GET query

Lý do: ?className=CNTT01 dễ lưu, chia sẻ và tải lại. Dùng trường className hiện có làm mã lớp.

Quy tắc: trim + viết hoa khi so sánh, khớp chính xác; chưa có bảng lớp riêng. Thống kê toàn bộ được giữ khi lọc.

D10 · OPERATIONS

Cổng 3000 mặc định, cấu hình qua PORT

Lý do: dễ chạy local bằng npm start, có thể đổi cổng mà không sửa code. Localhost là máy đang chạy ứng dụng.

Vận hành: npm run dev dùng node --watch; trang sinh viên có Cache-Control: no-store; body form giới hạn 10 KB.
