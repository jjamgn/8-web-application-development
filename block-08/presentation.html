01 / TỔNG QUANCHỨC NĂNG ĐÃ TRIỂN KHAI

Mục tiêu của website

🍜

Khu vực người dùng

  • Danh sách và chi tiết món ăn được render bằng EJS.
  • Tìm kiếm, lọc danh mục/trạng thái, sắp xếp và phân trang.
  • Chế độ database đọc qua Prisma; demo dùng dữ liệu mẫu trong mã nguồn.
  • ID sai hoặc món không tồn tại trả về 404.

URL chính: GET /dishes · GET /dishes/:id

🛠️

Khu vực quản trị

  • Quản lý món ăn (Dish), đầu bếp (Chef), nguyên liệu (Ingredient).
  • Chế độ database yêu cầu đăng nhập quản trị.
  • Validate dữ liệu, CSRF, xác nhận xóa và xử lý lỗi.
  • Demo cho xem giao diện; thao tác ghi bị chặn.

URL chính: /admin/dishes, /admin/chefs, /admin/ingredients

Luồng SSR: server render HTML bằng EJS; GET chỉ đọc. Tạo dùng POST, sửa dùng PATCH và xóa dùng DELETE. JavaScript gửi PATCH/DELETE bằng fetch; form có dự phòng khi tắt JavaScript.

05 / QUAN HỆ DỮ LIỆUĐÃ TRIỂN KHAI

Quan hệ giữa món, đầu bếp và nguyên liệu

Quan hệ 1 — N

Chef → Dish

  • Một đầu bếp có thể phụ trách nhiều món.
  • Dish.chefId tham chiếu khóa chính của Chef.
  • Không xóa đầu bếp khi còn món liên quan (Restrict).

Thông tin đầu bếp hiển thị trên trang chi tiết món.

Quan hệ N — N

Dish ↔ Ingredient

  • Bảng nối DishIngredient lưu từng cặp món–nguyên liệu.
  • Trường quantity ghi định lượng cho một phần.
  • Khóa chính ghép: dishId + ingredientId.
  • Xóa món sẽ xóa dòng nối; nguyên liệu đang dùng không thể xóa.

Hành vi HTTP trong source

  • GET chỉ đọc; xóa cần qua trang xác nhận.
  • Tạo dùng POST; sửa PATCH; xóa DELETE.
  • JavaScript gửi PATCH/DELETE qua fetch; tắt JavaScript thì dùng POST + method-override.
  • Database mode yêu cầu admin và CSRF; demo chặn ghi với 503.
  • Thành công redirect 303; dữ liệu sai trả 400; ID lỗi hoặc thiếu trả 404.

08 / DATABASE SETUPAN TOÀN THÔNG TIN

Supabase và coding agent: ai làm gì?

Nhóm thực hiện

  • Tạo project Supabase và lưu mật khẩu an toàn.
  • Tự điền DATABASE_URL vào file .env cục bộ.
  • Kiểm tra .gitignore có loại trừ file bí mật.
  • Review lệnh thay đổi schema trước khi chạy.
  • Kiểm tra dữ liệu trong database sau khi seed/CRUD.

Coding agent thực hiện

  • Tạo .env.example với placeholder.
  • Viết Prisma schema và script seed.
  • Chuẩn bị lệnh migration hoặc db push.
  • Viết hướng dẫn cấu hình và chạy project.
  • Không yêu cầu hoặc in mật khẩu database thật.
Không gửi mật khẩu thật trong prompt/chat hoặc commit lên Git. Nếu agent chạy trong workspace có quyền đọc file, hãy giả định nó có thể đọc file .env. Chỉ cấp quyền và thông tin cần thiết; nếu bí mật bị lộ, cần xoay vòng thông tin xác thực và cập nhật cấu hình.

09 / CẤU TRÚC & KIỂM THỬSOURCE HIỆN TẠI
